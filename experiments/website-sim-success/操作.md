### 最新修复 🔧（2026-01-14 01:25）
**问题原因**：浏览器CORS策略阻止直接访问扣子API
- 错误信息：`Failed to fetch`
- 根本原因：从 `localhost:8080` 直接请求 `https://2hft83qmjs.coze.site` 被浏览器拦截
- ASR/TTS 已通过代理，但扣子AI仍直连外部API

**修复方案**：
1. **server.js 新增 `/api/coze` 代理端点**
   - 接收前端请求
   - 服务器端持有扣子Token（不暴露到浏览器）
   - 转发请求到扣子API并返回SSE流

2. **前端改为调用本地代理**
   ```javascript
   // 修改 COZE_CONFIG.url
   url: '/api/coze'  // 原来是 https://2hft83qmjs.coze.site/stream_run
   ```

3. **统一架构**
   ```
   浏览器 → /api/aliyun/config → 服务器 → aliyun_config.json
   浏览器 → /api/aliyun/tts   → 服务器 → 阿里云TTS
   浏览器 → /api/aliyun/asr   → 服务器 → 阿里云ASR
   浏览器 → /api/coze         → 服务器 → 扣子AI
   ```

### server.js 核心功能
**API端点**：
1. **GET /api/aliyun/config**
   - 返回：`{success: true, token: "xxx", appkey: "xxx"}`
   - 自动读取aliyun_config.json
   - 如Token过期，自动调用Python脚本刷新

2. **GET /api/aliyun/tts**
   - 参数：appkey, token, text, voice, format等
   - 功能：代理阿里云TTS请求，解决CORS
   - 返回：音频流（audio/mpeg）

3. **POST /api/aliyun/asr**
   - URL参数：appkey, token
   - Body：WAV音频文件（binary）
   - 功能：代理阿里云ASR一句话识别
   - 返回：JSON `{status: 20000000, result: "识别文字"}`

**已知问题**：
- 服务器在后台终端运行时不稳定，容易退出
- 建议使用独立PowerShell窗口启动（Start-Process方式）

### 音频处理流程
1. **录音**：MediaRecorder录制WebM格式
2. **重采样**：OfflineAudioContext转为16kHz
3. **格式转换**：AudioBuffer → WAV PCM 16bit
4. **WAV文件结构**：
   - RIFF头（44字节）
   - fmt chunk（PCM格式声明）
   - data chunk（音频数据）
