## 问题诊断

### 发现的问题
阿里云服务器返回502错误，无法访问网页和API。

### 根本原因
nginx配置文件损坏 - `proxy_set_header` 指令的值被PowerShell变量污染。

**损坏的配置示例：**
```nginx
proxy_set_header Host \System.Management.Automation.Internal.Host.InternalHost;
proxy_set_header Upgrade \;
proxy_set_header X-Real-IP \;
```

**原因：** 之前使用PowerShell脚本生成配置时，nginx变量（如`$host`、`$http_upgrade`）被PowerShell解释为变量并替换。

## 修复方案

### 1. 创建修复脚本
- 文件：`server-deploy/fix-nginx-clean.sh`
- 功能：清理所有损坏的配置，重新生成正确配置

### 2. 正确的nginx配置
```nginx
server {
    listen 80;
    server_name cryptowatch.sifuture.cn;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        
        # 正确的变量引用
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        
        # SSE支持
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }
}
```

## 经验教训

### 1. 不要用PowerShell生成nginx配置
PowerShell会将 `$variable` 解释为变量，导致nginx配置损坏。

**错误做法：**
```powershell
$config = @"
proxy_set_header Host $host;
"@
```

**正确做法：**
```bash
# 使用bash脚本或heredoc
cat > config << 'EOF'
proxy_set_header Host $host;
EOF
```

### 2. 修改配置前先检查
```bash
# 测试配置语法
sudo nginx -t

# 查看实际配置内容
cat /etc/nginx/sites-enabled/cryptowatch
```

### 3. 保留备份
修复脚本自动备份旧配置：
```bash
sudo cp /etc/nginx/sites-enabled/cryptowatch \
  /etc/nginx/sites-enabled/cryptowatch.backup.$(date +%Y%m%d_%H%M%S)
```
